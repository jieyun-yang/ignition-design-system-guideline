# Figma
## Overview

This document outlines key Figma assets and their intended usage within our design system. These assets serve as foundational resources for streamlined design workflows, project alignment, and efficient creation of user interfaces.

## Usage Guidelines

### Big Rock Template

*   **Purpose**: Functions as the single source of truth for "big rock" projects, ensuring alignment across Design, Product Management (PM), and Engineering on the planned scope of work.
*   **Content**: Primarily dedicated to housing the confirmed, planned scope for a project.
*   **Exploration**: Earlier exploration, ideation, and shaping activities should be conducted in designated 'shaping' and 'playground' pages, separate from the core planned scope in the main template.

### Component Library

*   **Purpose**: Provides a collection of standardized, pre-built components to accelerate the design process.
*   **Application**: Used to quickly assemble and create designs, ensuring consistency and adherence to the design system guidelines.

## Anatomy/Structure

### Big Rock Template Structure

The Big Rock Template is designed with distinct sections to manage project evolution:

*   **Planned Scope Pages**: The core area containing finalized design work and confirmed features. This represents the agreed-upon deliverables for the project.
*   **Shaping Pages**: Dedicated areas for early-stage conceptualization, problem framing, and initial design exploration before commitment to the planned scope.
*   **Playground Pages**: Sections for experimental designs, alternative solutions, and speculative explorations that are not yet ready for formal shaping or integration into the planned scope.

## Best Practices

*   **Utilize Big Rock Templates for Alignment**: Always start "big rock" projects with the provided template to ensure all stakeholders (Design, PM, Engineering) are aligned on the single source of truth for the project's planned scope.
*   **Separate Exploration from Scope**: Use the dedicated 'shaping' and 'playground' pages within the big rock template for initial exploration and ideation. Keep the main planned scope pages focused on confirmed designs.
*   **Leverage the Component Library**: Always build designs using components from the central component library to ensure consistency, efficiency, and adherence to the design system.
*   **Maintain Single Source of Truth**: The big rock template for a project should be the definitive reference for what is being built.
