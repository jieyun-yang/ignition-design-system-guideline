# Toasts
This document outlines the guidelines for using "Toasts" within the design system, a component designed to provide brief, non-intrusive feedback to users.

---

## Overview

Toasts are temporary, non-modal messages that appear briefly to inform users of an outcome or event without interrupting their workflow.

## Anatomy/Structure

A default toast consists of the following elements:

*   **Icon**: Visually indicates the type of toast (e.g., success, error) using default styles.
*   **Heading**: A concise description of the situation or outcome.
*   **Close button**: Allows the user to manually dismiss the toast.
*   **Body**: An optional area for providing additional context or details about the situation.

## Usage Guidelines

Toasts should be used to provide timely feedback to users after an action. The type of toast used depends on the nature of the feedback:

| Type          | Description                                                                                                                                                                                               |
| :------------ | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Success**   | Confirms a successful action or task completion. Closes automatically after 5 seconds, unless an action button is present, in which case it remains until manually closed.                                |
| **Error**     | Informs that an error occurred or a task was unsuccessful. Remains until closed manually (Dual action) or closes automatically (Single action).                                                          |
| **Warning**   | Warns of an issue. Remains until closed manually (Dual action) or closes automatically (Single action).                                                                                                   |
| **Information** | Provides neutral information. Remains until closed manually (Dual action) or closes automatically (Single action).                                                                                      |
| **Waiting**   | Displayed while the system is mid-task. Once the process is complete, the toast is generally followed up by a success or error toast.                                                                     |
| **Premium**   | Not currently used in the application.                                                                                                                                                                    |

## Variants/States

Toasts can appear in different configurations based on the information they need to convey:

| Variant             | Description                                                                    |
| :------------------ | :----------------------------------------------------------------------------- |
| **Without body copy** | Used when no additional context is required beyond the heading.                |
| **With a link**     | Used when an action is required or recommended to the user.                    |
| **With 2 links**    | A unique toast used only for bulk actions where two distinct lists are involved. |

## Properties/Options

Toasts have configurable behaviors and styling options:

| Property       | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| :------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Trigger**    | Toasts are triggered as a result of a user action and appear immediately after the action. <br> _Example: After submitting a form, a toast provides feedback that the submission was successful._                                                                                                                                                                                                                                                                                                                                                                      |
| **Close Behavior** | Whether a toast closes automatically can be adjusted per toast. ## Overview

Toasts are temporary, non-modal messages designed to provide brief, non-intrusive feedback to users regarding an outcome or event without interrupting their current workflow.

## Anatomy/Structure

A default toast comprises the following visual elements and their purposes:

*   **Icon**: Indicates the specific type of toast (e.g., success, error) and utilizes default styles.
*   **Heading**: A concise textual description of the situation or outcome.
*   **Close button**: An interactive element (typically an "X" icon) that allows the user to manually dismiss the toast.
*   **Body**: An optional area that provides additional context or more detailed information related to the situation.

## Usage Guidelines

Toasts should be employed to deliver timely and relevant feedback to users following an action. The selection of the toast type is determined by the nature of the feedback:

| Type          | Description                                                                                                                                                                                                                                                                         |
| :------------ | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Success**   | Confirms a successful action or task completion. It closes automatically after 5 seconds, unless an action button is present, in which case it remains visible until manually dismissed.                                                                                              |
| **Error**     | Informs the user that an error occurred or that a task was unsuccessful. Depending on the configured close behavior, it either remains until closed manually (Dual action) or closes automatically (Single action).                                                                    |
| **Warning**   | Warns the user of an issue. Depending on the configured close behavior, it either remains until closed manually (Dual action) or closes automatically (Single action).                                                                                                                  |
| **Information** | Provides neutral, general information. Depending on the configured close behavior, it either remains until closed manually (Dual action) or closes automatically (Single action).                                                                                                   |
| **Waiting**   | Displayed while the system is actively processing a task. Once the process is complete, this toast will transition to a corresponding success or error toast.                                                                                                                         |
| **Premium**   | This toast type is currently not utilized within the application.                                                                                                                                                                                                                   |
