# ONBOARDING
This document outlines guidelines and patterns for onboarding users within the design system, ensuring a consistent and effective introduction to features and processes. It covers various components and best practices for engaging new and existing users.

## Usage Guidelines

### Onboarding Patterns

The following components can be used for various onboarding scenarios:

| Component | Usage |
| :-------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Full-page | Use at the beginning of a multi-step wizard or process to give users context about the process and the outcome. |
| Carousel modal | Use to explain important, complex concepts. |
| Zero-state Empty state | If there is no data on the page, use the zero-state empty state to briefly tell users what they'll see and do on this page, and how they can populate it. |
| Intro banner | If there is already data on the page, you can use a banner to: <br>- Provide context about the page to new users<br>- Promote a new feature to an existing user and encourage them to engage with it.<br>(New visual design TBC) |
| Benefits modal | Use sparingly to celebrate major milestones. |
| Product tour (via Intercom) | Use to provide in-context information about a specific function on a page or encourage users to interact with it. Aim for less than 5 tooltips per series for optimal engagement. |
| Page description | Use to add clarity to the page where required. This is static text and can't be dismissed. |
| Intercom banners and posts | Used for marketing and sales engagement. |

## Best Practices

### Do's

*   **Do use empty states to educate users.**
    *   If a page is empty, use a zero-state empty state to educate users about the page and how they can populate it.

### Don'ts

*   **Don't show multiple onboarding components at the same time.**
    *   If you have a lot to say, consider:
        *   Spacing the content out over the user's journey.
        *   Triggering content to appear after a certain event.
        *   Using an image or diagram to help explain complex concepts.
        *   Linking to a help article, video, or demo.
