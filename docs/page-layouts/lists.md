# Lists
```markdown
## Overview

Lists are fundamental UI elements used to organize and display information in a structured, readable format. They help users quickly scan and understand groups of related items, steps, or definitions. This guideline covers the various types of lists, their appropriate usage, and best practices to ensure consistency and accessibility across all products.

## Usage Guidelines

Use lists to present information clearly and efficiently. Choose the list type that best conveys the relationship between items and the intent of the content.

*   **Ordered Lists (`<ol>`):** Use for items where the sequence or order is important.
    *   Examples: Step-by-step instructions, rankings, chronological events, or items that must be completed in a specific order.
    *   **Do:** Use when the count of items or their specific position matters (e.g., "Step 1 of 5").
    *   **Don't:** Use for items where the order is arbitrary.
*   **Unordered Lists (`<ul>`):** Use for items where the order is not significant.
    *   Examples: A list of features, ingredients, requirements, or a collection of related but non-sequential items.
    *   **Do:** Use when items are equally important and do not require a specific sequence.
    *   **Don't:** Use when the sequence or hierarchy of items is critical for understanding.
*   **Description Lists (`<dl>`):** Use to display a list of terms and their corresponding descriptions or values.
    *   Examples: Glossaries, metadata, key-value pairs, or product specifications.
    *   **Do:** Ensure each term (`<dt>`) has at least one description (`<dd>`).
    *   **Don't:** Use for general lists of items that don't have a direct "term-definition" relationship.

## Anatomy/Structure

A list is composed of a container element and one or more list items.

*   **List Container:** The parent element (`<ul>`, `<ol>`, or `<dl>`) that defines the type of list.
*   **List Item (`<li>`):** Each individual item within an ordered or unordered list. It can contain text, links, or even other nested lists.
*   **List Marker:** The visual indicator (bullet, number, letter) that precedes each list item.
*   **Description Term (`<dt>`):** A term or name in a description list.
*   **Description Definition (`<dd>`):** The description or value associated with a description term.

## Variants/States

### Basic Lists

#### Unordered List

```html
<ul>
  <li>List item one</li>
  <li>List item two</li>
  <li>List item three</li>
</ul>
```

#### Ordered List

```html
<ol>
  <li>First item</li>
  <li>Second item</li>
  <li>Third item</li>
</ol>
```

#### Description List

```html
<dl>
  <dt>Term 1</dt>
  <dd>Description for term 1.</dd>
  <dt>Term 2</dt>
  <dd>Description for term 2, potentially longer and spanning multiple lines.</dd>
  <dd>Another description for term 2.</dd>
</dl>
```

### Nested Lists

Lists can be nested to create hierarchical structures. Limit nesting depth to a maximum of three levels to maintain readability.

```html
<ul>
  <li>Parent item 1</li>
  <li>
    Parent item 2
    <ul>
      <li>Child item 2.1</li>
      <li>
        Child item 2.2
        <ol>
          <li>Grandchild item 2.2.1</li>
          <li>Grandchild item 2.2.2</li>
        </ol>
      </li>
    </ul>
  </li>
  <li>Parent item 3</li>
</ul>
```

### Styled Lists (Optional)

In some contexts, default list markers might be replaced with custom icons or removed entirely, often in component-specific implementations (e.g., navigation menus, card lists).

```html
<ul class="list-unstyled">
  <li>Item without marker</li>
  <li>Another item without marker</li>
</ul>

<ul class="list-icon-check">
  <li>Feature with checkmark</li>
  <li>Another feature with checkmark</li>
</ul>
```
